## Project Overview

Rust-MQ is a Kafka-inspired message queue system in Rust. It supports single-broker and multi-broker (Raft consensus) deployments, using gRPC (Tonic) for communication and Protobuf for message serialization.

## Commands

```bash
# Build
cargo build --release

# Run tests
cargo test
cargo test <test_name>          # Run single test
RUST_LOG=debug cargo test       # With debug logging

# Lint
cargo clippy

# Format
cargo fmt

# Run broker (single-node)
cargo run -- --mode broker

# Run producer/consumer
cargo run -- --mode producer --config config/producer.yaml
cargo run -- --mode consumer --config config/consumer.yaml

# Run examples
cargo run --example producer_consumer
cargo run --release --example benchmark

# Criterion benchmarks
cargo bench

# Cluster management scripts
./scripts/start-cluster.sh      # Start 3-node Raft cluster
./scripts/stop-cluster.sh
./scripts/test-failover.sh
```

## Architecture

### Deployment Modes

- **Single broker**: Uses `InMemoryStorage`, no consensus. For dev/testing.
- **Multi-broker cluster**: Uses `MultiBroker` + `SimpleRaft` with Raft consensus for HA. Needs 3+ nodes.

### Request Flow

```
CLI (main.rs)
  └─> run_broker(): creates storage → BrokerCore → KafkaBrokerServer (gRPC)
  └─> run_producer/consumer(): loads config → Producer/Consumer → KafkaBrokerClient (gRPC)

Producer.send() → batch accumulation → flush → KafkaBrokerClient.Produce() (gRPC)
  └─> KafkaBrokerServer (Tonic) → mpsc channel → BrokerCore.handle_produce()
  └─> BrokerStorage.produce_message() → response with offset

Consumer.start(handler) → poll loop → KafkaBrokerClient.Fetch() (gRPC)
  └─> BrokerCore.handle_fetch() → BrokerStorage.fetch_messages()
  └─> MessageHandler.handle() → auto-commit offset
```

### Key Abstractions

- **`BrokerStorage` trait** (`src/broker/storage.rs`): Interface for all broker state. Two implementations:
  - `InMemoryStorage`: HashMap-based, single-node
  - `MultiBroker`: Wraps `SimpleRaftStorage`; returns error if node is not Raft leader

- **`BrokerCore<S>`** (`src/broker/core.rs`): Generic request handler parameterized on storage. Receives `BrokerGrpcRequest` variants via mpsc channel from the gRPC server.

- **`KafkaBrokerServer`** (`src/broker/kafka_broker_server.rs`): Tonic gRPC server implementing the `Broker` service from `kafka.proto`. Forwards to `BrokerCore` and awaits response.

- **`MessageHandler` trait** (`src/client/consumer.rs`): Custom message processing logic for consumers.

### gRPC API (`src/api/kafka.proto`)

Services: `GetTopicMetadata`, `Produce`, `Fetch`, `ListOffsets`, `FindCoordinator`, `JoinGroup`, `SyncGroup`, `Heartbeat`, `LeaveGroup`, `CommitOffset`, `FetchOffset`.

The generated Rust code lives in `src/api/broker.rs` (auto-generated by `build.rs` using `tonic-build`).

### Raft Cluster Components

`src/broker/simple_raft.rs` wraps the `raft` crate's `RawNode`. Key types:
- `BrokerData`: The replicated state machine (topics + messages + offsets)
- `BrokerCommand`: Commands applied via Raft (`Produce`, `CommitOffset`)
- `RaftNetwork` (`raft_network.rs`): Inter-node gRPC communication
- `RaftStateMachine` (`raft_state_machine.rs`): Applies committed log entries

### Configuration

YAML configs are deserialized into `AppConfig` (client) or `BrokerConfig` (broker). Key consumer offset values: `-2` = earliest, `-1` = latest, `0+` = specific offset. Cluster nodes must all appear in `initial_members`; set `bootstrap: true` only on the first node.
